# Implementation Plan
Use this doc to track features, assign owners, and connect to QA flows.

## Process
1. Capture feature request → link to `docs/product/feature-roadmap.md`.
2. Assign to skill owner (frontend/backend/devops/QA).
3. Document requirements, acceptance criteria, and QA flows for each feature.
4. Track progress via `.windsurf/workflows/feature-delivery-workflow.md`.
5. Close feature when QA verification and architecture reviews pass.

## Template Entry (per feature)
- **Feature**: [name]
- **Owner**: [skill]
- **Requirement**: [link to product doc/QA flow]
- **Status**: Draft / In Progress / Blocked / Done
- **QA Checklist**: [link to `docs/planning/qa-checklist.md` entries]
- **Architectural Notes**: [link to ADR if needed]

Use this doc as a living log for the team; include direct references to the QA flows to remain traceable.
